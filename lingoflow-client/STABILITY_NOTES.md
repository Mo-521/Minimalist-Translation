# LingoFlow 主界面稳定记录

本文只适用于主界面项目：`C:\Users\rioin\Desktop\极简翻译1.0\lingoflow-client`。

`desktop-tools` / `desktop-float-ball` 是桌面翻译子功能。除非明确要求，本记录不把它当作主界面的一部分直接改写。当前集成方式是：主界面作为产品壳，启动桌面翻译模块；proxy/server 作为用户、额度、用量和翻译记录的事实来源。

## 当前已验证状态

- 主界面可启动，并显示用户页、额度页、翻译页。
- 主界面用户页可以在测试用户之间切换。
- 用户、额度、近 7 天用量从 proxy/server 读取，不再依赖主界面本地 quota JSON。
- 近 7 天用量 X 轴使用 `Day 1` 到 `Day 7`，避免日期显示错位。
- 翻译页已清理为桌面翻译控制模块，不再保留主界面文本翻译框和结果框。
- 主界面“启动桌面翻译”可以启动 launcher。
- launcher 退出后，主界面运行状态会较快刷新。
- 目标语言选择会写入共享配置，桌面翻译模块读取同一目标语言。
- 划词翻译成功后，用量会通过 proxy/server 进入主界面用户/额度展示。
- 额度消耗按有效字符数计算，仅成功翻译计入用量。
- 测试用户额度隔离已可验证：切换用户后查看各自额度和用量。

## 当前产品边界

- 主界面负责：用户展示、额度展示、用量展示、翻译页入口、桌面翻译运行状态、目标语言配置。
- 桌面翻译模块负责：launcher、划词监听、识别框、悬浮翻译气泡、本地系统交互。
- proxy/server 负责：翻译请求、token 鉴权、额度计算、额度领取、用量历史、用户摘要。
- 共享配置负责：server base URL、beta token、目标语言、测试用户列表。

## 仍需稳固的风险

- 仍是测试 token 用户系统：目前适合内测，不适合正式账号体系。
- 主界面与桌面翻译仍是两个 Electron 项目：启动、退出、打包版本必须保持一致，否则用户会看到“终端启动”和“主界面启动”不一致。
- 桌面翻译运行状态依赖进程检测和轮询：极端情况下可能有 1 到 2 秒延迟。
- 共享配置是本地 JSON：适合当前阶段，但未来需要迁移到更明确的设置管理方案。
- proxy/server 的测试用户和额度数据仍需要正式持久化方案；当前阶段更像 beta 后台。
- Electron 安全配置后续仍需收紧：`nodeIntegration`、`contextIsolation`、远程资源、本地文件访问都需要在打包前复查。
- 打包链路还未完全冻结：主界面包、桌面翻译包、内置 backend/proxy 配置需要一次完整出包验证。

## 下一步建议

1. 固化交付版本：整理主界面和桌面翻译的启动路径、配置路径、版本号、打包命令。
2. 做一次打包验证：确认从打包后的主界面启动 launcher、切换测试用户、查看额度、选择目标语言、划词翻译、更新用量全都正常。
3. 整理 beta 测试说明：写明三个测试用户、额度规则、如何领取额度、如何判断是否走 proxy。
4. 再进入正式用户系统：把测试 token 替换为登录/注册/会话 token，不再把测试用户写死在客户端配置里。
5. 最后再做代码合并：等启动、用量、用户、额度这四条接口都稳定后，再把两个 Electron 项目合并成一个安装包。

## 当前推荐路线

先不要急着大合并。现在最稳的路线是：

```text
主界面稳定展示
-> 打包验证
-> beta 测试说明
-> 正式用户系统
-> 一个安装包合并
```

这样做可以避免“功能能跑，但合并后不知道哪里坏了”的情况。
